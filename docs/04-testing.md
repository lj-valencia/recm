# 04 — Testing

## Philosophy

This package computes numbers that people put in policy documents. A wrong
answer that runs cleanly is the failure mode that matters, so the test suite is
built around **independent-route verification**: every fast or clever
implementation is checked against a slow obvious one.

Coverage of lines is not the target. Coverage of *invariants* is.

## The mandatory invariant tests

Each maps to a numbered invariant in `CLAUDE.md`. **These must never be
relaxed or deleted.**

```r
test_that("alpha <-> a round-trips exactly", {          # INVARIANT 1
  for (m in 1:6) {
    a <- c(-runif(1, .05, .5), runif(m - 1, -.4, .4))
    expect_equal(a, .alpha_to_a(.a_to_alpha(a)), tolerance = 1e-12)
  }
})

test_that("k_norm[1] equals A(1)A(beta)", {             # INVARIANT 3
  k <- c(1, 27.6486, 3.2239); beta <- 0.98
  fs <- factorise_spectral(k, beta)
  s  <- .scalars(fs$alpha, beta)
  # k_norm, not k. The package normalises k_0 = 1, so the factorisation
  # constant cc is 40.29781 here, not 1 -- docs/02 section 3.
  expect_equal(fs$k_norm[1], s$A1 * s$Ab, tolerance = 1e-10)
})

test_that("closed-form Z matches brute-force summation", {   # INVARIANT 4
  # ... build a VAR companion H, then
  h  <- .hvec(alpha, beta, H, sel = 2L)
  d  <- .dweights(alpha, beta, 600)
  Hi <- H; bf <- 0
  for (i in 0:600) { bf <- bf + d[i + 1] * (Hi %*% z)[2]; Hi <- Hi %*% H }
  expect_equal(drop(h %*% z), bf, tolerance = 1e-10)
})

test_that("h_i equal the long division of A(1)A(beta)/A(beta F)", {  # INV 5

test_that("Riccati and spectral agree for small m", {   # INVARIANT 6
  for (m in 2:4) {
    k <- c(1, sort(runif(m, .5, 30), decreasing = TRUE))
    expect_equal(.lq_alpha(k, 0.98)$alpha,

  }
```

## Statistical tests

Recovery tests are inherently noisy. Rules:

- **Fix the seed.** Every simulated fixture sets `set.seed()` explicitly.
- **Never test a point estimate against truth with a tight tolerance.** The
  criterion is nearly flat; a single draw can sit two standard deviations out
  and that is correct behaviour. Test that truth lies inside the reported
  confidence interval, or run a small Monte Carlo and test the *mean*.
- **Separate bias from variance.** The pattern that works:

```r
test_that("estimator is unbiased on a known PAC DGP", {
  MC <- t(sapply(1:40, function(b) { set.seed(500 + b); ... }))
  expect_lt(abs(mean(MC[, "a0"]) - a0_true), 0.4 * sd(MC[, "a0"]))
})
```

Forty replications is enough to catch a real bias and cheap enough to run in
CI. Do not turn this into a 1000-replication test.

## Fixtures

`data-raw/dgp.R` builds the synthetic dataset: a common nominal stochastic
trend driving a smooth I(1) target and an observed income series with a
transitory component. Moments are calibrated to Canadian nominal non-durable
goods consumption and household disposable income — mean quarterly log growth
around 0.0104 and 0.0124, target smoothness ratio around 3.

Two variants are needed and both must be kept:

- **`dgp_ecm`** — `y` generated by a backward-looking ECM. Tests that the
  forward-looking specification *approximates* it (residuals near white noise).
- **`dgp_pac`** — `y` generated by the actual PAC rule with the same `alpha`
  the estimator will try to recover. This is the only fixture where parameter
  recovery is a meaningful test.

Using `dgp_ecm` for a recovery test is a mistake that looks like a passing
test. There is no true `alpha` to recover.

## Regression tests

`test-regression.R` freezes numbers from a fixed fixture and seed. When one
fails, that is information, not an inconvenience:

1. work out *which* invariant or numerical route changed
2. if the mathematics is now more correct, update the frozen value **and add a
   NEWS.md entry explaining the change**
3. if you cannot explain the change, the change is a bug

**Do not batch-update frozen values to make the suite green.**

## Optimiser tests

Nelder-Mead is the default and it is not reliable in one pass. Tests that
exercise the optimiser must:

- use `restarts >= 3`
- assert on the objective value, not only on the parameters — two very
  different `theta` can give nearly identical criteria, which is the whole
  identification problem
- for the direct-minimisation cross-check, start from a sensible point.
  Starting a 12-dimensional path optimisation from a flat guess stalled two
  decimal places short after 10,000 evaluations; starting from the target path
  matched the exact quadratic-program solution to 5e-08.

## Performance guardrails

`.lq_alpha()` at m = 20 converges in about 80 iterations. `.hvec()` at m = 20
with a 9-dimensional VAR state solves a 180x180 system. Neither is a
bottleneck, but a GMM fit evaluates both a few hundred times.

Add a guardrail test if you touch either:

```r
test_that("m = 20 estimation stays under 60 seconds", {
  skip_on_cran()
  expect_lt(system.time(recm_estimate(..., m = 20))[["elapsed"]], 60)
})
```
